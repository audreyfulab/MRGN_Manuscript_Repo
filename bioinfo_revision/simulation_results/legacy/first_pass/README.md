# `legacy/first_pass/` — the superseded inference run

The complete first pass of the revision pipeline: one simulation of 1,500 trios and the
inference of MRGN, MRPC, GMAC and MR-GGI over it, plus the confusion tables built from
them. Archived **2026-08-22**, when the trios were re-simulated under different effect
sizes and the whole run was invalidated.

Nothing in the pipeline reads this folder. It is kept because the numbers in
[`../../../METHODS.md`](../../../METHODS.md) and in `tables/confusion_matrices.md` were
measured here, and because the simulated data behind it was overwritten in place — these
files are the only surviving record of what that simulation looked like.

## What is here

| files | what |
| --- | --- |
| `selection_group_n{50,150,300,670,1000}.RData` | confounder-selection cache, one per sample-size group |
| `selection_results.{RData,csv}` | selection scored against the truth, all groups |
| `{mrgn,mrpc,gmac,mrggi}_group_n*.RData` | per-method group checkpoints |
| `inference_{mrgn,mrpc,gmac,mrggi}.{RData,csv}` | per-method combined results, 1,500 rows |
| `inference_results.{RData,csv}` | the four joined on `dataset` |

Column definitions are unchanged and documented in [`../../README.md`](../../README.md);
`tables/` is described in [`../../results_scripts/README.md`](../../results_scripts/README.md).

## Provenance

The simulated data was generated by `simulation/updated_data_simulation.R` as of commit
`9ba6ab1` *(Split selection stage and add method checkpoints)*. The inference ran under
`95d6262` *(Add MR-GGI pipeline and confusion reports)* — which is also the commit that
raised the `b.snp` / `b.med` floors, so the committed simulation script already did **not**
match this data by the time the inference finished. The table below is therefore the
authority on what generated these results, not the script at any one commit.

It is not archaeology: `b.snp` and `b.med` are per-trio columns of `inference_mrgn.RData`,
so the first-pass draws can be read back directly and were used to confirm the ranges below.

```r
load("inference_mrgn.RData")
aggregate(cbind(b.snp, b.med) ~ effect_size, mrgn.results, min)
#   effect_size  b.snp  b.med
# 1       large 1.0027 0.5009
# 2      medium 0.5008 0.3001
# 3       small 0.0000 0.0003     <- the 0.0 floors, as below
```

## Simulation parameters

Design, **identical in both passes** (`updated_data_simulation.R`): `set.seed(234)`;
5 models × 5 sample sizes (50, 150, 300, 670, 1000) × 3 effect sizes × 20 replicates =
1,500 trios, 300 per sample-size group. Residual `SD = 1`; one intermediate (`W_n = 1`) and
one common child (`Z_n = 1`) per trio; `U_n ~ sample(1:50)` capped at
`sample.size - W_n - Z_n - 4`, realized range 1–50; `K_n = 3` clinical covariates at n = 670
only, 0 elsewhere; `minor.freq ~ seq(0.01, 0.5, 0.01)`.

What changed for the current run:

| parameter | first pass (this folder) | current run |
| --- | --- | --- |
| `b.snp` small | `c(0.0, 0.5)` | `c(0.1, 0.5)` |
| `b.snp` medium | `c(0.5, 1.0)` | unchanged |
| `b.snp` large | `c(1.0, 1.5)` | unchanged |
| `b.med` small | `c(0.0, 0.3)` | `c(0.1, 0.3)` |
| `b.med` medium | `c(0.3, 0.5)` | unchanged |
| `b.med` large | `c(0.5, 1.0)` | unchanged |
| `conf.coef.ranges$K` | `c(0.00, 0.00)` | unchanged |
| `conf.coef.ranges$U` | `c(0.00, 0.30)` | `c(0.05, 0.30)` |
| `conf.coef.ranges$W` | `c(0.05, 0.50)` | `c(0.05, 0.30)` |
| `conf.coef.ranges$Z` | `c(1.00, 1.50)` | `c(0.30, 0.50)` |

`b.snp` / `b.med` are drawn per trio by `draw.effect.sizes()` from the stratum its
`effect_size` names; the `conf.coef.ranges` are the per-confounder coefficient bounds passed
to `simData.from.graph()` inside `simulate.dataset()` (`simulation/simulation_utils.R`),
from which `gen.conf.coefs()` draws `|a|` and flips the sign at `neg.freq = 0.5`.

### Why each moved

- **The `0.0` floors on the small stratum.** A `b.snp` draw near zero removes the `V1 -> T1`
  edge, so a `model0` trio is generated with no edges at all while still carrying the `M0.1`
  truth label; `b.med` near zero does the same to `model1`, `model2` and `model4`. The
  concern is written up at `updated_data_simulation.R:52-54`, which argues the lower bound is
  safe because `runif()` does not return its endpoint — true, but it does return 0.0003, and
  the small stratum was drawing effects too weak to be detectable by any method. Raising both
  floors to 0.1 makes "small" mean small rather than sometimes absent.
- **`U` floored at 0.05**, for the same reason one level down: a confounder with a
  coefficient of ~0 is not a confounder, and it inflated `n.true.confs` with variables that
  confound nothing.
- **`W` capped at 0.30** to match `U`. Both are drawn against the real GTEx Whole Blood PC
  effects measured in [`../../../pc_distribution_invest/README.md`](../../../pc_distribution_invest/README.md)
  (±0.20 at the central 95%, ±0.27 at 99%), and 0.50 sat well past that distribution.
- **`Z` from `c(1.0, 1.5)` down to `c(0.3, 0.5)`** — the largest change. The common child was
  loaded more heavily than anything observed in real data, which made it trivially detectable
  and dominated the collider results: GMAC selects the trio's own common child about half the
  time at n = 670, and adjusting for a collider on T1 and T2 manufactures a T1–T2 edge. The
  lopsided GMAC tables in `tables/confusion_matrices.md` are largely this parameter.

Realized confounding, as a check on the last three: median `R2(T1 | U)` was **0.453** here
and is 0.496 in the current run (0.459 / 0.508 for T2), against 0.41 cis / 0.31 trans in the
real Whole Blood data.

## Known gaps in this run

Carried forward so they are not rediscovered from the files:

- **MRPC ran to completion but was never tabulated.** All five group checkpoints and the
  full 1,500-row `inference_mrpc.*` are here, but `tables/` has no MRPC matrices — adding
  them is a copy of `confusion_mrgn.R` against the `mrpc.CSq.*` columns. Two caveats in the
  data itself: 224 of the 1,500 CS-q fits hit the 120 s timeout and carry `model = NA` with
  `timed.out = TRUE`; and the CS-α arm was switched off partway through because it does not
  terminate, so only 364 trios have a real CS-α result and the other 1,136 record the reason
  in `mrpc.CSa.error` rather than a silent `NA`. The measurements behind that decision are
  in `inference_config.R:21-41`.
- **MRGN model calls were backfilled.** 114 trios had `NA` models, not because `infer.trio()`
  failed to classify them but because the bootstrap that runs afterwards threw and took the
  finished call with it. A one-off `backfill_mrgn_models.R` recovered them; that script was
  never committed, and the comments at `results_scripts/confusion_utils.R:44-50` are the
  surviving description of what it did. The pre-backfill MRGN results are kept separately
  in [`../../pre_backfill_backup/`](../../pre_backfill_backup/).
- **The two calibration figures** (`simulated_vs_real_conf_effects.png`,
  `r2_vs_confounder_count.png`) were left at `simulation_results/` root and are overwritten
  by the next `verify_simulation.R` run, so this folder has no copy of the first pass's.
